# Plan — Milestone `v0.4.x Polish`

> Execution guide written for a smaller model. Read this top-to-bottom before touching
> code. Every issue number below (e.g. `#355`) is a GitHub issue in repo `Jolls/Arx` —
> open it with `gh issue view <n> --repo Jolls/Arx` for the full original description.
> This plan is the authoritative scope; the issue body is the detail.

---

## Context — why this work exists

`v0.4.1 Security & Hardening` shipped (current `main` is `v0.4.1`). The `v0.4.x Polish`
milestone is the follow-up sweep: **small, isolated bug fixes, latent-bug hardening, and
doc/TODO cleanup — no new user-facing behavior.** The goal is to clear the backlog of
low-risk correctness and tidiness items that accumulated during the Ruby→Go port, leaving
the codebase clean before `v0.5 Merged Arx` (the architectural merge of both apps).

This plan covers **17 issues**. Four issues that are tagged into the milestone but are
actually *features* (behavior changes) are **explicitly excluded** — see
[Excluded](#excluded-from-this-milestone) at the bottom.

## Repo facts you must respect (cheat-sheet)

- **Two Go apps**, both go-chi + getlantern/systray + `go:embed`, sharing `arxlib/`:
  - `parts_master_go/` — parts/suppliers/POs, port **4568**, exe `ArxPartsMaster.exe`
  - `test_records_go/` — test records viewer, port **4569**, exe `ArxTestRecords.exe`
- **Go workspace**: root `go.work` ties `arxlib`, `parts_master_go`, `test_records_go`.
- **Build**: `cd parts_master_go & build.bat` (and same in `test_records_go`). Each
  `build.bat` parses the version from the top `## [x.y.z]` of `CHANGELOG.md`, runs tests,
  then `go build` with `-H windowsgui`. Exes are gitignored.
- **DB**: SQL Server via `github.com/microsoft/go-mssqldb`. `SELECT *` preserves exact
  column-name casing. Never hardcode table names — use `cfg.*Table()`. SQL in `SQL/*.sql`
  is **reference DDL, not auto-run**; edit it to stay in sync, but it executes nothing.
- **Handler DB calls** (`parts_master_go`): always `h.queryContext` / `h.queryRowContext`
  / `h.execContext` / `h.beginTx` — never `h.db.*`. `test_records_go` has the same wrappers.
- **Branching**: never commit to `main`. One **feature branch per batch** below, push, open
  a PR. Branch names are given per batch.
- **Changelog**: one entry per PR/merge (not per commit), under a single `## [0.4.x]`
  version header. Format: `- <app>: <one-line summary> ([#NNN](https://github.com/Jolls/arx-legacy/issues/NNN))`.
  Suggested lines are given per batch.
- **RELEASE_NOTES.md** (kept identical in both app dirs): only update on a *user-facing*
  release. Most issues here are internal — do **not** touch RELEASE_NOTES unless told.
- **Closing issues**: add a one-sentence resolution comment (PR # / approach), then close.

### Verification baseline (run after every batch)
```bat
cd parts_master_go & build.bat
cd test_records_go & build.bat
```
Both must print `Built ...` with no test failures. `build.bat` runs `go test` and aborts
on failure, so a green build = tests pass.

#### #382 — `go.mod` says Go 1.22, workspace toolchain is newer  · `sev: med`

- In all three module files, change the `go` directive to match `go.work`:

#### #380 — arxlib tests run twice per full build  · `sev: low`
- Both `build.bat` line 22 run `go test ./<app>/... ./arxlib/...`, so building both apps
  tests `arxlib` twice.
- **Recommended fix**: drop `./arxlib/...` from each app's `build.bat` (line 22 → `go test ./<app>/...`)

- **Verify**: run both `build.bat` (green, arxlib not double-tested) and `test.bat` (green).

#### #349 — `start.ps1` launches deleted Ruby apps  · `sev: high`

  ```powershell
  Start-Process "$root\parts_master_go\ArxPartsMaster.exe"
  Start-Process "$root\test_records_go\ArxTestRecords.exe"
  ```
  Add a note that the exes must be built first (`build.bat`).
- **Verify**: build both exes, run `start.ps1`, confirm both apps come up (tray icons /
  `http://localhost:4568` and `:4569`). In TEST_MODE, confirm `_Test` tables are used.

### BATCH B — Database correctness  ·  branch `feature/v0.4.x-db`
Issues: **#355, #378, #367, #360**

#### #355 — `nullableInt` returns a string (and a caller panics on it)  · `sev: med`
- `parts_master_go/handlers/suppliers.go:664`. Current: returns `s` (raw string) when non-empty.
- Fix:
  ```go
  func nullableInt(s string) interface{} {
      if s == "" {
          return nil
      }
      if n, err := strconv.Atoi(s); err == nil {
          return n
      }
      return nil
  }
  ```
- Confirm `strconv` is imported (add if needed). The caller `i := v.(int)` at line 658 is
  now safe because the value is an `int`.
- **Verify**: build green. Manually exercise supplier-part create/update with a non-numeric
  `default_contact` — no panic, treated as null; numeric value still binds.

#### #378 — Test-mode PO sequence seed can collide  · `sev: med`
- `SQL/_test.sql:153`. If `PO_Test.number` holds any non-numeric value,
  `MAX(TRY_CAST(...))` → NULL → `ISNULL(...,0)` → seed `1`, which collides with snapshot data.
- **Recommended minimal fix**: raise the `ISNULL` floor so an all-non-numeric table still
  seeds safely above real PO numbers, e.g.:
  ```sql
  DECLARE @next_po INT = (SELECT ISNULL(MAX(TRY_CAST(number AS INT)), 99999) + 1 FROM dbo.PO_Test);
  ```
  (Confirm `99999` is above the realistic real-PO range first; bump if needed.)
- This is reference DDL — also keep `SQL/schema.md` in sync if it documents the seed.
- **Verify**: run `SQL/_test.sql` against the DB, then in TEST_MODE create a PO and confirm
  no PK/number collision.

#### #367 — `defer tx.Rollback()` causes double-rollback noise on success  · `sev: low`
- Sites: `parts_master_go/handlers/pos.go` (~313, ~380), `parts_master_go/handlers/parts.go`
  (~616, ~684, ~1114), plus any other `defer tx.Rollback()` followed by `tx.Commit()`.
  Grep `defer .*Rollback` to find them all.
- Pattern (use the `h.beginTx` `*txLogger`, not `h.db`):
  ```go
  committed := false
  defer func() { if !committed { tx.Rollback() } }()
  // ... work ...
  if err := tx.Commit(); err != nil { /* handle */ }
  committed = true
  ```
- **Verify**: build green; with `DEBUG_MODE=true`, create a PO and confirm no spurious
  rollback log line appears after a successful commit.

#### #360 — `hide_formula` nil-context call paths — audit only  · `sev: med`
- `test_records_go/handlers/hide_formula.go` + call sites in `handlers/records.go`
  (~319, ~932, ~1118, ~1414). `evaluateHide()` is called with nil results/record on
  form-definition pages; tokens stay unresolved and the step defaults to *shown*.
- This is **audit + document**, not a rewrite. Cross-check against issue **#210**'s spec.
  At each nil-context site, confirm "show on inconclusive evaluation" is the intended
  behavior for that view and add a one-line comment saying so.
- **If the audit reveals a genuine logic bug, STOP and report to the user** — don't
  silently change hide/show behavior.
- **Verify**: build green; form-definition page renders all steps (none wrongly hidden).

**Changelog (Batch B)**
```
- parts_master_go: nullableInt now parses to int instead of returning a string ([#355](https://github.com/Jolls/arx-legacy/issues/355))
- parts_master_go: harden test-mode PO sequence seed against non-numeric data ([#378](https://github.com/Jolls/arx-legacy/issues/378))
- parts_master_go: avoid double-rollback log noise on committed transactions ([#367](https://github.com/Jolls/arx-legacy/issues/367))
```

### BATCH C — Runtime & infra hardening  ·  branch `feature/v0.4.x-infra`
Issues: **#364, #363, #359, #379, #381, #366**

#### #364 — Hardcoded 600ms sleep before opening browser  · `sev: low`
- Both apps, in `main.go`. `parts_master_go/main.go:61` — `time.Sleep(600ms)` then
  `browser.OpenURL(url)`. `test_records_go/main.go` has the same block.
- Fix: poll the port until it accepts a connection, then open. `cfg.Port` is available.
  ```go
  for i := 0; i < 40; i++ {
      c, err := net.DialTimeout("tcp", "127.0.0.1:"+cfg.Port, 50*time.Millisecond)
      if err == nil { c.Close(); break }
      time.Sleep(50 * time.Millisecond)
  }
  _ = browser.OpenURL(url)
  ```
  Add `net` import; `time` already imported.
- **Verify**: run each app; browser opens once the server is actually accepting connections
  (no "site can't be reached" on cold start).

#### #363 — `Content-Disposition` not RFC 6266 quoted  · `sev: low`
- `parts_master_go/handlers/files.go:83` (`attachment; filename="`+base+`"`, quote
  unescaped) and `test_records_go/handlers/files.go:28` (unquoted).
- Fix both (keep the existing `.pdf → inline` branch unchanged):
  ```go
  w.Header().Set("Content-Disposition",
      mime.FormatMediaType("attachment", map[string]string{"filename": filepath.Base(path)}))
  ```
  Add `mime` import in each file.
- **Verify**: download a normal-named file from each app — header well-formed, download works.

#### #359 — `folderpick.BrowseFolder` has no timeout — handler can hang  · `sev: med`
- `arxlib/folderpick/folderpick.go`. `BrowseFolder()` runs `powershell ... .Output()` with
  no timeout; an abandoned dialog blocks the HTTP handler goroutine forever.
- Fix (keep backward-compatible): add `BrowseFolderContext(ctx context.Context) string`
  using `exec.CommandContext`, and keep `BrowseFolder()` as a wrapper that calls it with a
  `context.WithTimeout(context.Background(), 5*time.Minute)`. Then update HTTP-handler
  callers to pass `r.Context()`. Grep `BrowseFolder(` to find callers.
- **Verify**: open the folder picker from Settings, select a folder — still works; abandoning
  the dialog no longer wedges the handler (it returns "" after the timeout / on cancel).

#### #379 — `console_windows.go` theoretical handle leak  · `sev: low`
- `parts_master_go/console_windows.go`. `openDebugConsole` allocs a console each call
  without closing the prior one. Called once at startup today.
- Minimal fix: add a package-level `var consoleOpen bool` guard so a second call is a no-op.
- **Verify**: build green; with `DEBUG_MODE=true`, the debug console still opens on startup.

#### #381 — `config/local.go` writes 0600 — verify Windows ACL  · `sev: med`
- `parts_master_go/config/local.go:47`: `os.WriteFile(localConfigPath, data, 0600)`. On
  Windows the Unix bits are cosmetic; the file holds the DB password, so real protection
  depends on the inherited folder ACL.
- Steps: first inspect the actual ACL — `icacls config\local.pm.json`. If non-owner users
  have read access, harden in `SaveLocal` after the write (e.g. shell out to `icacls` to
  disable inheritance and grant only the current user).
- **This one needs real Windows testing.** If the ACL is already owner-only by inheritance,
  document that and close with no code change.
- **Verify**: `icacls config\local.pm.json` shows access limited to the owner (+ SYSTEM/Admins).

#### #366 — `render()` panic risk — VERIFY ONLY  · `sev: med`
- Both apps' `render()` already guard with `data.(map[string]any)`. Confirm test_records_go's
  `render` has the same guard (grep `func (h \*Handler) render`). If both guard, add a short
  comment and **close the issue as already-resolved**. No fix expected.
- **Verify**: grep confirms the type assertion exists in both apps.

## Per-PR checklist (repeat for each batch)

1. `git switch -c feature/v0.4.x-<area>` off `main` (confirm you're not on `main`).
2. Make the batch's edits.
3. `cd parts_master_go & build.bat` and `cd test_records_go & build.bat` — both green.
4. Run the per-issue **Verify** steps above.
5. Add the batch's changelog lines under one new `## [0.4.2] - <date> ` header
   in `CHANGELOG.md` (reuse the same version header across all four PRs of this milestone —
   confirm the exact next version with the user; `0.4.2` is a placeholder).
6. Commit (end message with the `Co-Authored-By: Claude Sonnet 4.6` trailer), push, open a PR.
7. After merge, comment + close each issue in the batch with a one-line resolution.
