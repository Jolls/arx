## Feature 1 — #156: Import a part's file into the PO folder  *(PM; no schema)*

**Goal:** From a PO line (which references a part), let the user pick one of that part's
`LOCAL:`-style attachment file links and copy the file into the PO folder.

**What exists to reuse** ([arx_go/pos.go](arx_go/pos.go)): `createPOFolder`, `findPOBaseFolder`,
`POFolder`/`POFolderSub`/`renderPOFolder`, and the PO-folder naming convention
([docs/conventions.md](docs/conventions.md)). Part attachments live in `AttachmentsTable()` with
`FILFileName` in the `LOCAL:`/`LOCAL:dir/`/http forms (see conventions).

**Approach:**
- New handler `POImportPartFile` `POST /po/{id}/import-part-file` (register near the other
  `/po/{id}/...` POST routes in [main.go](arx_go/main.go)): inputs = PO id + chosen part attachment
  id (or its resolved local path). Resolve the part's `LOCAL:` link to an absolute source path,
  resolve the PO base folder via `findPOBaseFolder`, copy the file in, redirect back to the PO.
  Guard: only `LOCAL:` links (http links have nothing to copy); skip/clear error if source missing.
- UI on [po_detail.html](arx_go/templates/pm/po_detail.html) line-items: a per-line "Add file to PO
  folder" affordance. Fetch-on-demand: a button hits an existing/new JSON endpoint returning that
  part's `LOCAL:` attachments, user picks one, posts to the import handler.
- **Tests:** a pure helper for `LOCAL:`-link → absolute-path resolution (the copy itself is IO).

## Feature 2 — #386: Hide/show columns on TR tables  *(TR; no schema, JS/CSS only)*

**Goal:** A **Columns** dropdown above each of the three TR tables toggles per-column visibility,
persisted in `localStorage`, with a **Reset** link. No server round-trip, no Go changes.

**Targets** (`templates/tr/`): `records_index.html`, `records_show.html`, `form_def.html` (the
14-column form-definition table is the priority — already 2400px wide).

**Approach** (mirrors the existing client-side toolbar in [static/pm/app.js](arx_go/static/pm/app.js)):
- Add `data-col="<key>"` to every `<th>` and matching `<td>`.
- A Bootstrap `Dropdown` of checkboxes (one per column) + Reset link in each table's toolbar.
- JS (extend [static/tr/app.js](arx_go/static/tr/app.js)): toggle a `.col-hidden { display:none }`
  class on `[data-col=key]`; persist to `localStorage` keyed `arx.cols.<table-id>`; restore on
  load; Reset clears the key and shows all.

## Feature 3 — #390: Filter-preserving back button  *(PM/cross-app; no schema)*

**Goal:** Returning from a detail page to a filtered/sorted list (e.g. POs) restores the filter and
sort the user had applied.

**Current state:** PO list filter + sort are entirely client-side with no URL/query state
([static/pm/app.js:78-139](arx_go/static/pm/app.js#L78)); back nav uses server-side `navBack(sess)`
which stores only a bare list URL.

**Approach (client-side, no Go change):**
- As the user edits filter inputs / changes sort, mirror that state into the URL via
  `history.replaceState`, so the list URL encodes the view.
- On list load, read that state back and re-apply filters/sort before first paint.
- `navBack` stores the list URL from the session referer; the encoded state rides along automatically.
  If it strips the query string, fall back to `sessionStorage` keyed by page.
- Scope to the PO list first; the mechanism generalizes to other app.js-driven list tables.

## Feature 4 — #403: TR archive/retire (replace `HIDE` workaround)  *(TR; schema migration)*

**Goal:** Explicitly archive a `test_definition` row instead of the `hide_formula="HIDE"` hack.
Archived steps are hidden from new records and the live definition view, but **still rendered on
historical records** that have results for that step. A toggle in the definition view shows/hides
archived rows. No hard deletes.

**Schema (additive, rollback-safe):**
- `test_definition` gains `archived BIT NOT NULL DEFAULT 0`.
- `SQL/test_definition.sql` DDL + idempotent `SQL/migrations/migrate_tr_archive.sql` +
  `SQL/_test.sql` rebuild + `SQL/SCHEMA.md`. Run manually on ArxProd + ArxDev.

**Go** ([records.go](arx_go/records.go), [models/trmodels.go](arx_go/models/trmodels.go)):
- Add `Archived` to the step model; select it where steps are loaded.
- **New records / live definition view:** filter out `archived` steps (leave
  [hide_formula.go](arx_go/hide_formula.go) untouched — `HIDE` literal stays supported).
- **Historical record view:** include an archived step iff that record has a result row for it.
- Archive/unarchive `POST` route + handler; no hard delete.

**Templates** (`templates/tr/`): `form_def.html` archived-row indicator + show/hide-archived toggle;
Archive button on `form_def_edit.html`.

**Tests:** archived step excluded from new record; archived step included when historical record has
its result; excluded when it doesn't.
