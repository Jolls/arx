# Plan — Issue #413: Merge Arx into a single local host (single port)

## Context

Arx already ships as **one binary** (`arx_go/Arx.exe`) but runs **two HTTP servers on two
ports**: Parts Master (PM, `partsmaster`, 4568) and Test Records (TR, `testrecords`, 4569).
The systray opens two browser tabs and the two apps cross-link via hardcoded
`localhost:4568`/`4569` URLs. Issue #413 ("Merge into single local host", milestone *v0.5
Merged Arx*) asks to collapse this to a **single port / single origin** so the two apps feel
like one app and can eventually cross-link cleanly.

**Key finding from exploration:** the two apps' *domain* routes are fully disjoint —
PM owns `/part*`, `/suppliers*`, `/pos*`, `/contacts*`; TR owns `/forms*`, `/records*`,
`/images*`, `/api/forms*`, `/api/named-query`. They collide **only** on shared infrastructure
routes that both register: `/` (home), `/settings` (+POST), `/whats-new`, `/static/*`,
`/local/*`, `/api/browse-folder`. Both `/local/*` handlers serve the same `DocControlRoot`,
and both `RELEASE_NOTES.md` are kept identical, so those can simply be shared.

**User decisions for this issue:**
1. **Parts Master stays at `/`** (it's the larger app). TR's forms list moves to `/records`.
2. **Unify settings now** — one settings page + one merged `config/local.json` (no more
   `local.pm.json` + `local.tr.json`).

Intended outcome: open `http://localhost:4568/`, land on Parts Master, reach Test Records at
`/records`, one Settings page configures everything, header links are same-origin. Minimal UI
changes — each app keeps its own templates/layout/look for now.

## Architecture of the merge

Keep both `App` instances (each builds its own chi router and its own DB pool). Combine them
at the HTTP layer in `arx_go`:

- **One `http.Server` on port 4568.** Its handler is **PM's router**, with **TR's router set
  as PM's `NotFound` fall-through**. Any path PM doesn't match falls to TR; TR's own
  `NotFound` remains the final 404. Because the route sets are disjoint after step 2, nothing
  is shadowed.
- **TR vacates the colliding infra routes** so PM owns them once:
  - `/` (TR `FormsList`) → **`/records`**
  - `/static/*` (TR) → **`/tr-static/*`**
  - `/settings`, `/whats-new`, `/api/browse-folder`, `/local/*` → **removed from TR**; PM's
    versions serve both apps (release notes are identical; `/local/*` serves the same
    `DocControlRoot`).
  - TR keeps `/images/*`, `/forms*`, `/records/{id}*`, `/api/forms*`, `/api/named-query`.
- **Settings unified:** one merged `config/local.json` read by both apps; PM's `/settings`
  page extended to include TR's `ImageRoot`; on save, **both** DB pools reconnect.

## Step-by-step

### 1. Shared single `local.json`
- Add `arxlib/config/local.go` with a single `LocalConfig` holding **all** fields (DB,
  `DocControlRoot`, `POFolderRoot`, `SupplierFilesRoot`, `PODefaultContactID/ReceiverID`,
  `ImageRoot`, `DebugMode`, `TestMode`, `TestDBName`) and `LoadLocal()/SaveLocal()` reading
  **`config/local.json`**. Mirror the existing JSON tags exactly.
  - One-time migration in `LoadLocal()`: if `config/local.json` is absent but
    `config/local.pm.json` and/or `config/local.tr.json` exist, read+merge them and write
    `config/local.json` (preserves the saved DB password so users don't re-enter it).
- Point both `parts_master_go/config/local.go` and `test_records_go/config/local.go` at the
  shared type (thin re-export aliases, e.g. `type LocalConfig = arxbase.LocalConfig`,
  `var LoadLocal = arxbase.LoadLocal`, `var SaveLocal = arxbase.SaveLocal`) so existing call
  sites in each package keep compiling. Delete the per-package struct/path/IO bodies.
- Both `config.Load()` functions already map only the fields they need from `LoadLocal()`;
  TR's `Load()` additionally maps `ImageRoot` (already does), PM ignores `ImageRoot`. No
  change to mapping logic beyond the type swap.

### 2. Unified Settings page (PM owns `/settings`)
- `parts_master_go/handlers/settings.go`: add `image_root` to `SettingsSave` (read form value,
  set `local.ImageRoot`) and to `settingsData` (expose `ImageRoot`). Because the shared
  `LocalConfig` now has `ImageRoot`, PM's save no longer drops TR's value.
- `parts_master_go/templates/settings.html`: add an **Image Root** field (used by Test
  Records) next to Doc Control Root.
- Add a **post-save reconnect hook** to PM's `Handler`: a field
  `AfterSettingsSave func()` (nil-safe), invoked at the end of `SettingsSave` after
  `SaveLocal`. PM still reconnects its own pool inline as today.
- Remove TR's `/settings`, POST `/settings`, `/whats-new`, `/api/browse-folder` routes from
  `test_records_go/main.go`; the `Settings/SettingsSave/WhatsNew/APIBrowseFolder` handlers and
  `templates/settings.html`, `templates/whats_new.html` in TR become dead — delete them.

### 3. TR reconnects on save
- Add `func (a *App) Reload() error` to `test_records_go/main.go`: re-run `config.Load()`
  (reads the freshly-saved `local.json`), reconnect the pool from `cfg.DSN()`, and swap the
  new `*sql.DB` + `*config.Config` into the handler (add a small `Handler` setter, e.g.
  `h.SetDBAndConfig(db, cfg)` that also re-runs `CheckSchemaVersion`). This refreshes TR's
  `DocControlRoot`/`ImageRoot`/`TestMode`/pool from disk in one shot.
- In `arx_go`, wire `pm`'s `AfterSettingsSave = func(){ _ = tr.Reload() }`.

### 4. TR router vacates infra routes
In `test_records_go/main.go` `buildRouter`:
- Change `/static/*` mount prefix to **`/tr-static/*`**.
- Change `GET /` (`FormsList`) to **`GET /records`**.
- Delete `/settings`, POST `/settings`, `/whats-new`, `/api/browse-folder`, `/local/*` routes.
- Leave `RequireAuth` redirect target as `/settings` (PM serves it on the combined router).

### 5. TR template repointing (minimal, mechanical)
Across `test_records_go/templates/*.html` (layout + ~11 others — `records_index`,
`records_show`, `record_new`, `record_edit`, `form_def`, `form_def_edit`, `form_new`,
`form_duplicate`, `not_found`):
- `/static/...` → `/tr-static/...` (css/js/favicon).
- `href="/"` (home / "back to forms" links, incl. `layout.html` navbar brand) → `/records`.
- Keep `/settings` and `/whats-new` links (now served by PM).
- `layout.html` cross-link: `.PartsMasterURL` link stays; its value becomes relative (step 6).

### 6. Same-origin cross-links
- `parts_master_go/config/config.go`: default `TestRecordsURL` → **`/records`**.
- `test_records_go/config/config.go`: default `PartsMasterURL` → **`/`**.
  (Header links in both layouts already render these; they just become same-origin paths.)

### 7. Combine in `arx_go` + single port + systray
- `parts_master_go/main.go`: store the chi router on `App` and expose
  `func (a *App) Handler() http.Handler` and `func (a *App) SetFallback(h http.Handler)`
  (sets the router's `NotFound` to `h.ServeHTTP`). Also expose the `AfterSettingsSave` wiring
  (e.g. `func (a *App) SetAfterSettingsSave(fn func())` forwarding to the handler).
- `test_records_go/main.go`: expose `func (a *App) Handler() http.Handler` returning its router.
- `arx_go/main.go`:
  - `pm := partsmaster.New(); tr := testrecords.New()`
  - `pm.SetFallback(tr.Handler())`
  - `pm.SetAfterSettingsSave(func(){ _ = tr.Reload() })`
  - Serve **one** `http.Server{Addr: "0.0.0.0:"+pm.Port, Handler: pm.Handler()}`. Stop
    serving `tr.Server` / opening a second port.
  - `openWhenReady` once for `pm.URL`.
  - Systray: collapse to a single **"Open Arx"** item → `pm.URL`; keep Quit. Keep the
    `pm.DebugMode || tr.DebugMode` debug-console check and `onExit` closing both apps.

## Verification

1. `cd arx_go && build.bat` — runs `go test ./...` then builds. Must pass. Fix any test that
   asserts an old route (TR middleware test asserts redirect to `/settings`, still valid).
2. Run `arx_go\Arx.exe` (from `arx_go\`). Confirm:
   - One browser tab opens at `http://localhost:4568/` → Parts Master parts list.
   - Header "Test Records" link → `/records` → forms list, **styled** (loads `/tr-static/app.css`).
   - Header "Parts Master" link from a TR page → `/` works.
   - A few deep routes resolve: `/part/{id}`, `/pos`, `/forms/{id}/records`, `/records/{id}`,
     `/images/...`, `/local/...`.
   - `:4569` is no longer listening.
3. Settings: open `/settings`, confirm it shows DB + Doc Control Root + **Image Root** + PO
   defaults. Save with a DB password → redirects to `/`, **both** apps connected (visit a PM
   page and a TR page without the settings redirect). Confirm a single `config/local.json` was
   written (and old `local.pm.json`/`local.tr.json` migrated on first load).
4. Toggle Test Mode in Settings, save → both apps point at `ArxDev` (TR record list + PM parts
   list both reflect dev DB).

## Toward a fully merged app (later roadmap, not yet issued)
These complete the collapse from "two apps stitched together" into one genuine app; each
removes a piece of the seam this issue intentionally leaves in place.
- Collapse `parts_master_go/` + `test_records_go/` + `arx_go/` into a single `arx_go` package (one `package main`, one module dir).
- Build one combined chi router directly — drop the PM-primary + TR `NotFound` fall-through trick.
- Single embedded `templates/` + `static/` set (one `/static`; retire the `/tr-static` namespace).
- One shared session cookie (retire the separate `arx-session` / `arx-tr-session`).
- One `RELEASE_NOTES.md` + one `CheckSchemaVersion` / schema-version constant (retire the kept-in-sync duplicates).
