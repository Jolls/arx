# #213 — Seed: fixed ids for `named_queries` rows

## Findings (verified 2026-09-27)

- The issue's stated failure **does not reproduce** on current `main`/this branch. Test in a throwaway
  `postgres:17` container: `build_schema.sh` (which already runs the seed once) followed by two more
  runs of `seed_test_data.sql`, and a full `build_schema.sh` re-run, all exit 0.
- Why it can't collide today: `DELETE FROM named_queries;` (line 82) runs before the INSERT
  (lines 122-152, **10** rows, no `id` column), all in one `BEGIN … COMMIT`. `setval(…, 99)`
  (line 719, `is_called = true`) means each re-run assigns ids 100-109 to an empty table. A fresh
  build assigns 1-10. The only effect is id drift (1-10 on a fresh build, 100-109 after any reseed).
  That drift is the real inconsistency with the fixed-ID convention.
- Nothing references `named_queries.id`: no FKs, and no other seed rows point at it. Go code
  (`arx_go/named_query.go`, `arx_go/named_query_settings.go`, settings backup) and integration tests
  (`TestIntegration_UpdatedAtSentinel`, `TestIntegration_RunNamedQuery_StaleSpecNomParamRename`,
  the `max_subbatch_result` DateStyle test) key off `name`. The Settings editor uses the id only
  round-trip from its own page. The migration `20260926120000_28_…` updates by name.
- A seed variant with ids 1-10 was run twice in the throwaway container. Both runs succeeded, the
  table held ids 1-10, and `nextval` returned 100.
- Only one schema doc exists: `SQL/SCHEMA.md`. `SQL/schema.md` resolves to it on case-insensitive
  Windows. There's no separate copy.
- No existing test reads `seed_test_data.sql` for structure. `arx_go/dead_schema_names_test.go` greps
  all `SQL/postgres/*.sql` files, but only for dead column and table names.

## Resolved decisions (user, 2026-09-27)
- Proceed with fixed ids as consistency hardening. The PR closes #213; the resolution comment says the stated collision didn't reproduce (DELETE runs first in one tx) and that the real defect was id drift between a fresh build and a reseed (1-10 vs 100-109).
- The test goes in a new `arx_go/seed_lint_test.go` (as below).
- Relabel `app_config` as "natural key" in the seed header and SCHEMA.md (as below).

### 3. New file `arx_go/seed_lint_test.go` (red test, see Test plan)

```go
package main

import (
	"os"
	"path/filepath"
	"regexp"
	"strconv"
	"strings"
	"testing"
)

// TestSeedNamedQueriesFixedIDs guards #213: seed_test_data.sql's named_queries
// rows carry fixed ids, like every other seed block, at or below the table's
// setval floor, so the reference set is identical on every (re-)run.
func TestSeedNamedQueriesFixedIDs(t *testing.T) {
	b, err := os.ReadFile(filepath.Join("..", "SQL", "postgres", "seed_test_data.sql"))
	if err != nil {
		t.Fatal(err)
	}
	seed := string(b)

	m := regexp.MustCompile(`setval\(pg_get_serial_sequence\('named_queries', 'id'\), (\d+)\)`).FindStringSubmatch(seed)
	if m == nil {
		t.Fatal("no setval for named_queries in seed_test_data.sql")
	}
	floor, _ := strconv.Atoi(m[1])

	start := strings.Index(seed, "INSERT INTO named_queries (")
	if start < 0 {
		t.Fatal("no INSERT INTO named_queries in seed_test_data.sql")
	}
	lines := strings.Split(seed[start:], "\n")
	if !strings.HasPrefix(lines[0], "INSERT INTO named_queries (id, ") {
		t.Errorf("named_queries INSERT must list id first: %q", lines[0])
	}

	rowID := regexp.MustCompile(`^\((\d+), '`)
	seen := map[int]bool{}
	for _, line := range lines[1:] {
		line = strings.TrimSpace(line)
		if strings.HasPrefix(line, "(") { // row start; continuation lines start with '
			rm := rowID.FindStringSubmatch(line)
			if rm == nil {
				t.Errorf("named_queries seed row without a fixed id: %q", line)
			} else {
				id, _ := strconv.Atoi(rm[1])
				if id < 1 || id > floor {
					t.Errorf("named_queries seed id %d outside 1-%d (setval floor)", id, floor)
				}
				if seen[id] {
					t.Errorf("duplicate named_queries seed id %d", id)
				}
				seen[id] = true
			}
		}
		if strings.HasSuffix(line, ");") {
			break
		}
	}
	if len(seen) == 0 {
		t.Error("no named_queries seed rows with fixed ids found")
	}
}
```

## Test plan

1. **Coverage audit.** No Go test inspects `seed_test_data.sql` structure. `dead_schema_names_test.go`
   only greps for dead names. The integration tests (`TestIntegration_UpdatedAtSentinel`, the
   `liveHandler` sentinel on part 3005) read seeded rows from ArxDev, but none checks named_queries
   ids or a double run.
2. **Characterization tests.** None are needed. There's no behavior change for code, and name-keyed
   lookups are already covered by the integration tests listed above.
3. **Red test:** `TestSeedNamedQueriesFixedIDs` (new `arx_go/seed_lint_test.go`) asserts three things:
   - the named_queries INSERT column list starts with `id`;
   - every row-start line begins with a numeric id;
   - ids are unique, within 1 and the parsed `setval` floor (99), and at least one row exists.

   It fails today because line 122's column list has no `id` and all 10 rows start with `('<name>'`.
   It passes after change 1.
   - Verify red: `go test ./arx_go/ -run TestSeedNamedQueriesFixedIDs` from the repo root, before
     editing the seed. Expect failures.
   - Verify green: the same command after change 1. Then run `go build ./... && go vet ./... && go test ./...`.
4. **Manual only:**
   - **Throwaway-container double run** (agent or human). Use a new container only. Never use
     `arx-pg`, `arxdev` or `deckshare-db-1`.
