# Plan — Issue #416: Integration tests against a live DB (build-tagged)

## Context
Level 3 of #240. Levels 1–2 (pure-function unit tests + no-DB `httptest` middleware
coverage) are done. This adds **live-DB round-trip tests** that exercise the full SQL stack:
identity inserts, triggers, sequences, and denormalized counts.

Hard constraints (from the issue):
- **Must be build-tagged `//go:build integration`** so the default `go test ./...` sweep —
  and therefore `arx_go/build.bat` and CI — never run them (no live SQL Server in CI).
- Run manually against the **ArxDev** database only; never prod.
- Document the manual run command + required env where test mode is described (CLAUDE.md).

## Design decision (important)
Test at the **handler-method level**, not through the full chi router. Construct a real
`*handlers.Handler` with a live `*sql.DB` pointed at ArxDev, then call the exported handler
methods directly with `httptest` requests + a `ResponseRecorder`.

Why: CSRF is enforced by the `RequireCsrfOnPost` *middleware*, not inside the handlers, so
calling methods directly needs **no CSRF token round-trip** — yet the real INSERT/UPDATE/DELETE
SQL still fires the DB triggers, sequences, and denormalized counts, which is the entire value
of Level 3. Routing + middleware + CSRF are already covered by #240's unit tests, so going
through the router again would add brittleness for no new coverage.

## Deliverable
**One new file:** `parts_master_go/handlers/integration_test.go`
- First line: `//go:build integration` then a blank line, then `package handlers` (white-box,
  same package as `middleware_test.go`, so it can reach `h.DB()` and unexported helpers).
- Imports: `context`, `net/http`, `net/http/httptest`, `net/url`, `os`, `strconv`, `strings`,
  `testing`, `time`, `github.com/go-chi/chi/v5`, `arx/parts_master_go/config`,
  `arx/parts_master_go/db`.

### 1. Harness `liveHandler(t *testing.T) (*Handler, *sql.DB, func())`
- `dsn := os.Getenv("ARX_TEST_DSN")`; if `""` → `t.Skip("set ARX_TEST_DSN (ArxDev) to run integration tests")`.
- **Prod safety guard:** if `!strings.Contains(strings.ToLower(dsn), "arxdev")` → `t.Fatal`
  ("integration tests must target the ArxDev database"). Never touch prod.
- `cfg := config.Load()` — gives the `cfg.*Table()` helpers; a missing `.env` only logs, it's
  non-fatal. Then `cfg.TestMode = true`.
- `database, err := db.Connect(dsn)`; `t.Fatal` on error.
- `h := New(database, cfg, nil, nil)` — nil templates/release-notes are fine because the happy
  paths all `http.Redirect` (302) and never render. (Limitation: if a handler hits its *error*
  path it will try to render with a nil FS and the body becomes "template parse error" instead
  of the SQL error. So tests assert `302` and on mismatch dump `rec.Body` — a non-302 means the
  handler errored; rerun with a real DB to see why.)
- Return `h`, `database`, and a `cleanup` closure that hard-deletes any rows this test created,
  in reverse-FK order (`FIL` rows for the part, then the `PN` row), then `database.Close()`.
  Track created IDs via a captured slice the tests append to, or just delete by the unique
  `part_number` prefix. Keep it simple.

### 2. Test `TestIntegration_PartLifecycle`
Exercises identity `OUTPUT INSERTED.PNID`, UPDATE, the `trg_FIL_part_count` trigger, and the
`PN.PNFILLinks` denormalized count — all self-contained (needs no pre-existing reference data).

Helper for direct calls that read `chi.URLParam(r, "id")` — inject a chi route context:
```go
func withID(req *http.Request, id int) *http.Request {
    rctx := chi.NewRouteContext()
    rctx.URLParams.Add("id", strconv.Itoa(id))
    return req.WithContext(context.WithValue(req.Context(), chi.RouteCtxKey, rctx))
}
func postForm(target string, vals url.Values) *http.Request {
    req := httptest.NewRequest(http.MethodPost, target, strings.NewReader(vals.Encode()))
    req.Header.Set("Content-Type", "application/x-www-form-urlencoded")
    return req
}
```

Flow:
1. **Create** — `PartsCreate`. Form: `part_number` = `"ITEST-"+strconv.FormatInt(time.Now().UnixNano(),10)`,
   plus `revision`, `title`, `release_status=U`, `active=1`. Assert `rec.Code == 302`. Parse the
   new PNID from `rec.Header().Get("Location")` (`/part/{id}` → strip prefix, `strconv.Atoi`).
   Register it for cleanup.
2. **Update** — `PartUpdate` with `withID(req, pnID)`. Change `title` to a new value (keep
   `part_number` non-empty — it's required). Assert 302. Then
   `h.DB().QueryRowContext(ctx, "SELECT title FROM "+h.cfg.PartsTable()+" WHERE PNID=@p1", pnID)`
   → assert it equals the new title.
3. **Attachment create + trigger** — `PartAttachmentCreate` with `withID(req, pnID)`. Form:
   `FILFileName` = `"http://example.test/itest"`, `FILPNRev`, `FILNotes`. Assert 302. Then query
   `SELECT PNFILLinks FROM PN WHERE PNID=@p1` → assert `== 1` (set by `trg_FIL_part_count`).
   Capture the new `FILID` for cleanup: `SELECT MAX(FILID) FROM FIL WHERE FILPNID=@p1`.
4. **Attachment soft-delete** — `PartAttachmentDelete` with route ctx carrying both `id` (pnID)
   and `attID` (the FILID). Assert 302. Then query `PNFILLinks` → assert `== 0` (trigger counts
   active rows only).
5. `cleanup` removes the FIL + PN rows.

Use a single `context.Background()` for verification queries.
