## Context — why this change

`v0.5 Merged Arx` is down to its foundational items. This is **Prerequisite #2** in
`docs/FUTURE_GOALS.md` and unblocks #240 (advanced tests).

Today `TEST_MODE=true` does **table-name mangling**: every `cfg.*Table()` helper returns a
`_Test` variant (e.g. `PN_Test`) that lives in the **same database** as prod (`dbo` schema).
This is structurally messy and the `_Test` suffix collides visually with Go's `_test.go`
convention.

**Goal:** make `TEST_MODE` a **DSN swap** to a separate `ArxDev` database on the same SQL
Server. The `*Table()` helpers then return bare prod names (`PN`, `PO`, …); the only thing
that changes between prod and test is *which database the connection points at*.

**Outcome:** `*Table()` helpers simplify to one line each; `_Test` tables are dropped from
prod; test data lives in its own `ArxDev` DB.

**Prod is unaffected.** With `TEST_MODE=false`, the DSN still uses the prod DB name and the
helpers already returned bare names — behavior is byte-identical. Only `TEST_MODE=true`
behavior changes. The Go change is therefore safe to merge before `ArxDev` is fully populated
(it just won't have data to serve until the SQL half is run).

## Part 1 — `arxlib/config/base.go`: DSN swap on TestMode

Add a configurable dev DB name and make the DSN use it when `TestMode`.

- Add field to `Base` (after `DBName`): `TestDBName string` — the database to use in test
  mode (default `ArxDev`).
- Add a helper:
  ```go
  // ActiveDBName returns the database the app should connect to: the dev DB in test mode,
  // otherwise the prod DB.
  func (b *Base) ActiveDBName() string { return Pick(b.TestMode, b.TestDBName, b.DBName) }
  ```
- In `BuildDSN`, change the `database` query value from `b.DBName` → `b.ActiveDBName()`.
- In `ConnectionSummary`, surface the active DB + a test marker, e.g.:
  ```go
  name := b.ActiveDBName()
  if b.TestMode { name += " (TEST)" }
  return fmt.Sprintf("%s / %s", b.DBServer, name)
  ```
- Keep `Pick` (still used here). It is no longer used by the app `*Table()` helpers after
  Part 2 — that's fine; it stays exported for `ActiveDBName`.

## Part 2 — both `config.go`: populate `TestDBName` + flatten `*Table()` helpers

Apply the **same pattern** to `parts_master_go/config/config.go` and
`test_records_go/config/config.go`.

**2a. Populate `TestDBName` in `Load()`** inside the `arxbase.Base{...}` literal:
```go
TestDBName: arxbase.GetEnv("TEST_DB_NAME", "ArxDev"),
```

**2b. Optional `local.json` override** (parity with `DBName`; keep it minimal):
- In each `config/local.go` `LocalConfig` struct add: `TestDBName string `json:"test_db_name,omitempty"``.
- In each `Load()` local-override block add: `if local.TestDBName != "" { cfg.TestDBName = local.TestDBName }`.
- No Settings-UI field needed — the dev DB name rarely changes from `ArxDev`.

**2c. Flatten every `*Table()` helper** to return the bare name. Drop the
`arxbase.Pick(c.TestMode, "X_Test", "X")` call; return `"X"`. Update the header comment from
"switches between prod and _Test variants" to "returns the table name (TEST_MODE swaps the
whole DB via the DSN — see Base.ActiveDBName)".

Representative (PM has ~13 helpers, TR ~11):
```go
func (c *Config) PartsTable() string    { return "PN" }
func (c *Config) POTable() string       { return "PO" }
func (c *Config) AppConfigTable() string { return "app_config" }
// …every helper in parts_master_go/config/config.go:111-123 and
//   test_records_go/config/config.go:79-91
```
`NamedQueriesTable()` already returns a bare name — leave it. **Keep the methods** (do not
inline at call sites): per FUTURE_GOALS the `*Table()` abstraction stays as the single control
point.

After this, `arxbase.Pick` is no longer imported/used by the app config packages — if the
compiler flags an unused import, remove it from that file (it is still used inside
`arxlib/config`).

## Part 3 — `parts_master_go/handlers/pos.go`: the hardcoded `_Test` sequence

`pos.go:296-299` hardcodes a `_Test` **sequence** name (sequences aren't covered by
`*Table()`). In the ArxDev model the dev DB has its own bare-named `PO_Number_Seq`, so the
conditional is obsolete. Replace:
```go
seqName := "dbo.PO_Number_Seq"
if h.cfg.TestMode {
    seqName = "dbo.PO_Number_Seq_Test"
}
```
with just:
```go
seqName := "dbo.PO_Number_Seq"
```
**Do NOT touch `pos.go:1028`** (`if h.cfg.TestMode { folderName += "-testmode" }`) — that is a
filesystem safety net so test-mode POs don't write into real PO folders, unrelated to DB
naming. Keep it. (All the other `"TestMode": h.cfg.TestMode` template-data lines are UI banner
flags — leave them all.)

## Part 4 — SQL (manual; reference scripts)

> These run against a live SQL Server by hand. `ArxDev` is assumed to be a separate database
> on the **same instance**, using the **same login** (only the `database` differs). Replace
> `ArxProd` below with the actual prod DB name configured in `local.*.json`.

**4a. Rewrite `SQL/_test.sql` → "populate ArxDev from prod."** Adapt the existing script:
- Run in the `ArxDev` context (`USE ArxDev;`) — or use three-part `ArxDev.dbo.X` targets.
- Source every table from prod via three-part names: `SELECT * INTO dbo.PN FROM ArxProd.dbo.PN;`
  (etc.) using **bare** target names (no `_Test`).
- **Include the config/shared tables** that the old `_test.sql` skipped because they were
  shared in one DB — `named_queries`, `release_notes`, `logs`, `app_config`, `unit` — ArxDev
  is now a full separate DB and needs its own copies.
- Recreate the constraints, the unique index, the CHECK, the four triggers, and the
  `PO_Number_Seq` sequence on the **bare-named** ArxDev tables (strip every `_Test` suffix from
  the current script's object names: `trg_FIL_Test_part_count` → `trg_FIL_part_count`,
  `PO_Number_Seq_Test` → `PO_Number_Seq`, etc.).
- Keep the snapshot-count recalibration and the sequence `RESTART WITH MAX+1` logic.
- Update the header comment to describe the new purpose.

**4b. New migration `SQL/migrations/drop_test_tables.sql`** — drops the now-dead prod `_Test`
objects. Pattern (one per object, guarded):
```sql
IF OBJECT_ID('dbo.PN_Test','U')          IS NOT NULL DROP TABLE dbo.PN_Test;
-- …all *_Test tables listed in the old _test.sql (lines 10-32)…
IF OBJECT_ID('dbo.PO_Number_Seq_Test','SO') IS NOT NULL DROP SEQUENCE dbo.PO_Number_Seq_Test;
```
Run this **only after** ArxDev is verified working. Destructive, but `_Test` tables are
disposable snapshots.

## Risk notes

- **Biggest risk is the SQL half**, which is unverifiable in-repo. The Go half is low-risk and
  prod-neutral. Consider merging only after the live-DB verify passes, or land the Go change
  and keep the PR open with a clear "ArxDev must be created" note.
- **ArxDev built via `SELECT * INTO` is data-only** (no FKs/identity/indexes beyond the few
  re-added), exactly like the old `_Test` tables. Building ArxDev from the full `SQL/*.sql`
  DDL is a cleaner future option but a much larger manual lift — out of scope here (matches the
  issue's "run _test.sql to populate" intent).
- No `app_config.schema_version` bump: this reroutes the connection, it does not change the
  tracked prod schema. ArxDev inherits `schema_version="2"` from the prod copy, so
  `CheckSchemaVersion` still matches in test mode.
- If a future table is added, it must be created in ArxDev too (re-run the populate script) —
  call this out in the updated CLAUDE.md checklist.
