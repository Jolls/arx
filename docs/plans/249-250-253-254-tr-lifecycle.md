# Plan: TR Issues #249, #250, #253, #254 — Record Lifecycle

> Created: 2026-06-24

## Context

Four TR lifecycle/UX features in three PRs. #249 grew (per design discussion) from a simple
"reviewer name" into a **three-state record lifecycle** (WIP → Complete → Approved) with a
permission-gated unlock. #250 (re-open reason) is mostly done — unlock already saves a reason to
`record_events`; the gap is **displaying** that log (audit panel). #253 is bulk "Mark Complete"
from the list. #254 is a one-click **Duplicate** (same SN, copies results) with no DB change.

## Approver identity (automatic)

"Who completed / approved / unlocked" is recorded server-side from `h.currentUser(r)` into the
existing `record_events` table — **no name input field**, and **no `reviewer_name`/`approved_at`
columns** (those were redundant; the events table already carries username + timestamp).

## PR A — #249 + #250: Three-state lifecycle + permission-gated unlock + audit log

A test record now moves through **three states**, replacing the single `is_locked` boolean
with a two-flag model:

| State | Flags | Set by | Unlock by | Badge |
|---|---|---|---|---|
| **WIP** | `is_locked=0` | (default) | editable by anyone | `bg-info` "WIP" |
| **Complete** | `is_locked=1, is_approved=0` | any user ("Mark Complete") | any user (reason required) | `bg-secondary` "Complete" |
| **Approved** | `is_locked=1, is_approved=1` | reviewer w/ permission ("Approve") | **only** reviewer w/ permission (reason required) | `bg-success` "Approved by X" |

Strict two-step: **Approve is only available on a Complete record** (not directly from WIP).
Existing locked records become **Complete** automatically (`is_approved` defaults to 0) — no
data migration, nothing lost.

## PR B — #253: Bulk Mark Complete

No DB change. Depends on PR A's "Complete" state (`event_type='completed'`); land PR A first.
Bulk action moves WIP records to **Complete** (never directly to Approved — approval stays a
deliberate per-record reviewer step).

### Handler (`arx_go/records.go`)

**`BulkLockRecords` (POST `/forms/{id}/records/bulk-lock`):**

- Parse `record_ids[]` from form body.
- Loop over each ID; for each:
  ```sql
  UPDATE test_record SET is_locked=1, updated_at=GETDATE()
  WHERE id=@p1 AND form_id=@p2 AND is_locked=0
  ```
  On `RowsAffected > 0`: insert `record_events` row (`event_type='completed'`).
- Count total completed. Redirect to `/forms/{id}/records?locked=N`.

Loop per-ID (not `IN(...)`) to validate form ownership per row without dynamic SQL.

**`RecordsList`:** Read `r.URL.Query().Get("locked")`, parse to int, add `"LockedCount"` to
render map.

### Routes (`arx_go/main.go`)

```go
r.Post("/forms/{id}/records/bulk-lock", h.BulkLockRecords)
```

## PR C — #254: Duplicate Record

**No DB change** (binary swap). Per user direction: drop the `source_record_id` traceability
column (no purpose for this shop), and the duplicate keeps the **same serial number** as the
source — it's the same physical unit being re-tested. No clone dialog: a one-click "Duplicate"
lands the user in the edit view, where Date and Type are already editable (set "RMA"/"Upgrade"
there). SN is read-only in the edit view, which is exactly the desired behavior.

### Handler (`arx_go/records.go`)

**`DuplicateRecord` (POST `/records/{id}/duplicate`):**

1. Load source record (same SELECT as RecordDetail, minus events).
2. Begin tx.
3. `INSERT INTO test_record` copying **all** carry-over fields as-is: `form_id,
   part_number_id, serial_number, serial_number_pn, serial_number_pn_desc, comments,
   instrument_type, test_order, record_date`; set `created_at=GETDATE(), is_active=1,
   is_locked=0`. Use `OUTPUT INSERTED.id` to get `newID`.
4. `SELECT` all `test_result` rows for the source record; `INSERT` each into the new record
   preserving all columns (`result`, `comment`, `pass_fail`, and all snapshot columns). Use
   `sql.NullString` / `sql.NullBool` for nullable columns.
5. Commit. Redirect to `/records/{newID}/edit`.

Pattern reference: `copyFormSteps()` in records.go (lines ~2050-2146) for the tx+copy loop;
`CreateRecord` + `materializeRecordSteps()` (~1277) for the `test_result` INSERT field list.

### Routes (`arx_go/main.go`)

```go
r.Post("/records/{id}/duplicate", h.DuplicateRecord)
```

### Duplicate button (`records_show.html`)

Always visible (locked or not). A POST form (it mutates), next to Export PDF:

```html
<form method="POST" action="/records/{{.Record.ID}}/duplicate" class="d-inline">
  <input type="hidden" name="csrf_token" value="{{.CSRFToken}}">
  <button type="submit" class="btn btn-sm btn-outline-secondary ms-2"
          onclick="return confirm('Create a duplicate of this record (same SN) for re-testing?')">
    <i class="bi bi-copy"></i> Duplicate
  </button>
</form>
```

### Verification

1. Build passes (no migration needed).
2. Duplicate button visible on all records (locked + unlocked).
3. Click Duplicate → new unlocked record created with the **same SN**, lands in `/records/{newID}/edit`.
4. All result rows copied (values pre-filled from source); edit Date/Type/results as needed and save.
5. Source record unchanged.
6. Duplicate a locked record → the duplicate is unlocked; source stays locked.

## Sonnet agent usage (token strategy)

All three PRs are specified precisely enough (exact files, line anchors, SQL, snippets)
that the *implementation* is mechanical pattern-following — ideal for Sonnet agents. Opus
stays in the loop for: reviewing each agent's diff before commit, resolving CHANGELOG version
conflicts if PRs land close together, and the build/test/PR steps.

| PR | Delegate to Sonnet? | Why |
|---|---|---|
| **A (#249+#250)** | **No — keep on Opus.** | Security-sensitive: permission gating on unlock, a new per-user auth flag, and a state-model change spanning `auth.go`, Settings, schema, and TR. CLAUDE.md flags auth/permission work as Opus-worthy. |
| **C (#254 duplicate)** | **Yes — highest ROI.** | Most verbose, lowest-risk code: the `test_result` copy-loop with `sql.NullString`/`sql.NullBool` scanning. Pure pattern-following from `copyFormSteps` (records.go ~2050) and `CreateRecord`/`materializeRecordSteps` (records.go ~1277). No schema, no template. |
| **B (#253 bulk complete)** | **Yes.** | Self-contained: one handler (loop over IDs) + template checkboxes + ~20 lines of vanilla JS. No auth/judgment calls. |

**Recommendation:** Opus implements PR A (auth + state model). Delegate PR B and PR C each to a
Sonnet agent with the relevant snippets + pattern line-ranges from this plan, then review diffs
and run `build.bat` before committing. When briefing an agent, point it at this plan section
plus the pattern source lines — do **not** let it re-explore the whole codebase.
