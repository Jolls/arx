## Context — why this work exists

`v0.4.x Polish` shipped (current `main` is `v0.4.2`). The `v0.5 Merged Arx` milestone is
**architectural prep to merge both apps into a single binary** (CLAUDE.md → Issue Triage).
The long-term end state (`FUTURE_GOALS.md` → "Architecture end state") is *one executable,
one port, with user authentication*. That full end state is **not** this milestone — it
requires user auth (#207) and a route/template rewrite. This milestone takes the **first,
safe step**: collapse the two `.exe` files into one binary, plus the refactor cleanups the
merge makes worth doing.

**Scope decision already made with the product owner:**
1. **PR1 merges to "one binary, two ports"** — a single `Arx.exe` with one systray icon that
   runs both apps on their existing ports (4568 + 4569). This is a pure structural refactor:
   **no route changes, no template-link changes, behavior-identical** to running the two
   exes today. The single-port collapse is explicitly deferred (see
   [Deferred](#deferred--later-in-this-milestone-or-its-own-plan)).
2. This plan **fully details** PR1 plus the refactor PRs that directly support the merge
   (#371, #370, #373, #375, #385, #372). The larger foundational items (auth #207, ArxDev
   #241, test infra #240) and the feature issues are **outlined only** — each warrants its
   own plan.

## Repo facts you must respect (cheat-sheet)

- **One binary, two library packages** sharing `arxlib/`:
  - `parts_master_go/` — `package partsmaster` — Parts catalog, suppliers, POs, port **4568**
  - `test_records_go/` — `package testrecords` — Test records viewer, port **4569**
  - `arx_go/` — `package main` — entry point; hosts both servers + systray, outputs `Arx.exe`
- **Go workspace**: root `go.work` ties `arxlib`, `arx_go`, `parts_master_go`, `test_records_go`
  (currently `go 1.26.3`). Modules import each other in workspace mode without `require`
  directives between them.
- **Build**: `cd arx_go & build.bat` — parses version from top `## [x.y.z]` of `CHANGELOG.md`,
  runs `go test ./parts_master_go/... ./test_records_go/... ./arxlib/...`, then `go build`
  with `-H windowsgui`. Output: `arx_go\Arx.exe`. Version injected into both app configs via
  `-ldflags -X arx/parts_master_go/config.AppVersion=<v> -X arx/test_records_go/config.AppVersion=<v>` —
  **never set `AppVersion` in code.**
- **DB**: SQL Server via `github.com/microsoft/go-mssqldb`. `SELECT *` preserves exact
  column-name casing. Never hardcode table names — use `cfg.*Table()`. SQL in `SQL/*.sql`
  is **reference DDL, not auto-run**; edit it to stay in sync, but it executes nothing.
- **Handler DB calls**: always `h.queryContext` / `h.queryRowContext` / `h.execContext` /
  `h.beginTx` — never `h.db.*`. Both apps have these wrappers.
- **Sessions**: gorilla cookie store. **The two apps use different cookie names already** —
  `parts_master_go` = `arx-session`, `test_records_go` = `arx-tr-session`. This is why a
  process-merge is safe (no cookie collision). Do not change these in PR1.
- **Branching**: never commit to `main`. One **feature branch per PR** below, push, open a
  PR. Branch names are given per PR. Each PR may be merged to `main` independently.
- **Changelog**: one entry per PR/merge (not per commit). Format:
  `- <app>: <one-line summary> ([#NNN](https://github.com/Jolls/arx-legacy/issues/NNN))`.
  Suggested lines are given per PR.
- **RELEASE_NOTES.md** (kept identical in both app dirs): only update on a *user-facing*
  release. The merge is mostly invisible to users; see PR1's note on what (if anything) to
  add.
- **Closing issues**: add a one-sentence resolution comment (PR # / approach), then close.

## ⚠️ Corrections / cautions found during planning — read before starting

1. **#385 needs a product decision before any code.** It is *not* a mechanical fix. The
   choice is "keep `pf_formula` long-term" vs "drop it." Default to **keep + document**
   (lowest risk); ask the user before choosing drop (drop means a migration + irreversible
   data orphaning). See PR3.
2. **#227 is outward-facing.** "Unprivate the repo" makes the code public — that is a
   publish action. **Do not make the repo public.** Only do the *audit half* (scan for
   secrets) and report; the publish decision is the user's. See Deferred.
3. **#372 (config dedup) is the biggest-surface refactor here and FUTURE_GOALS says to defer
   it "until a third app appears."** The merged main in PR1 arguably *is* that third
   consumer, so it's now defensible — but it is optional and risky. It is sequenced **last**
   (PR4) so a lesser model can stop after the safe work if unsure.
4. **`SaveLocal` does not create its directory.** It calls `os.WriteFile("config/local.*.json")`
   with no `MkdirAll`. The merged binary's working dir must contain a `config/` folder or
   the first Settings save fails. PR1 §D handles this.
5. **Server-error handling:** preserve each app's existing behavior on a failed
   `ListenAndServe` (log + clean shutdown so `onExit`/`CloseDB` runs). Do **not** introduce
   `log.Fatal` in the merged main — it would skip `onExit` and leave DB pools open. (#365
   established this intent for the single-app case.)

## ~~PR1 — Merge the executables (one binary, two ports) · #218 (part 1)~~ ✅ DONE — PR #404

> Merged to main as v0.5.0. Both app dirs are now library packages. `arx_go/Arx.exe` is
> the single binary. One gotcha found during execution: `go test ./...` doesn't work from
> the workspace root (root isn't a module) — use explicit paths, matching `test.bat`.

Branch: `feature/v0.5-merge-binary`

### Success criteria (the whole point)
Running **one** `Arx.exe` produces **one** systray icon and serves **both** apps:
`http://localhost:4568` (Parts Master) and `http://localhost:4569` (Test Records), each
behaving exactly as before. Quitting from the tray shuts down both servers and closes both
DB pools. The two old exes are gone.

### Why it's shaped this way
`go:embed` can't reach across packages, and a directory is one package. So to let a new
"merged main" import each app's HTTP server, **each app directory must become an importable
library package**, and the process-level glue (systray, browser-open, debug console, icon)
must move out into the merged main. Two ports stay, so **no route or template link changes
are needed** — that is what keeps this PR low-risk.

### Steps

**A. Convert `parts_master_go/` from `package main` → library package `partsmaster`.**
- In `main.go`, `embed.go`: change `package main` → `package partsmaster`.
- **Delete** `parts_master_go/icon.go` and `parts_master_go/console_windows.go` — they move
  to the merged main (they are byte-identical between the two apps; de-dup them there).
- Rework `main.go` (rename it `app.go` for clarity): remove `func main`, the `systray.*`
  calls, the browser-open goroutine, and the `appHandler` global. Keep `buildRouter`
  unchanged. Replace `onReady`/`onExit` with a constructor and a close method:
  ```go
  package partsmaster

  type App struct {
      Server *http.Server
      URL    string // "http://localhost:" + cfg.Port
      Port   string
      Name   string // "Parts Master"
      Debug  bool   // cfg.DebugMode
      h      *handlers.Handler
  }

  func New() (*App, error) {
      cfg := config.Load()
      var database *sql.DB
      if dsn := cfg.DSN(); dsn != "" {
          if conn, err := db.Connect(dsn); err == nil {
              database = conn
              log.Println("parts_master: auto-connected to database")
          } else {
              log.Printf("parts_master: auto-connect failed: %v", err)
          }
      }
      h := handlers.New(database, cfg, templatesFS, releaseNotesData)
      h.CheckSchemaVersion(context.Background())
      return &App{
          Server: &http.Server{Addr: "0.0.0.0:" + cfg.Port, Handler: buildRouter(h)},
          URL:    "http://localhost:" + cfg.Port,
          Port:   cfg.Port, Name: "Parts Master", Debug: cfg.DebugMode, h: h,
      }, nil
  }

  func (a *App) Close() { a.h.CloseDB() }
  ```
  `templatesFS`, `staticFS`, `releaseNotesData` stay in `embed.go` (now `package partsmaster`)
  and keep working because the embedded dirs are still in the same directory.

**B. Same conversion for `test_records_go/` → library package `testrecords`.** Identical
shape; `Name: "Test Records"`, port 4569.

**C. Create the merged main.** New top-level directory `arx_go/`:
- `go.mod`: `module arx/arx_go` (same `go 1.26.3` directive as the others).
- Add `./arx_go` to the `use (...)` block in root `go.work`. In workspace mode the merged
  main can then `import ("arx/parts_master_go"; "arx/test_records_go")` with no `require`
  lines. (If a standalone `go build ./arx_go` ever complains outside the workspace, add
  `require` + `replace arx/parts_master_go => ../parts_master_go` and likewise for
  test_records — but verify workspace build first; you likely won't need it.)
- `arx_go/main.go` (`package main`):
  ```go
  func main() { systray.Run(onReady, onExit) }

  var pm *partsmaster.App
  var tr *testrecords.App

  func onReady() {
      var err error
      if pm, err = partsmaster.New(); err != nil { log.Printf("parts_master init: %v", err) }
      if tr, err = testrecords.New(); err != nil { log.Printf("test_records init: %v", err) }

      if (pm != nil && pm.Debug) || (tr != nil && tr.Debug) { openDebugConsole() }

      serve(pm)   // each: go a.Server.ListenAndServe(); on error -> log.Print + systray.Quit()
      serve(tr)

      systray.SetIcon(appIcon())
      systray.SetTooltip("Arx")
      mPM   := systray.AddMenuItem("Open Parts Master", "")
      mTR   := systray.AddMenuItem("Open Test Records", "")
      systray.AddSeparator()
      mQuit := systray.AddMenuItem("Quit", "Quit Arx")
      // goroutine: select on the three ClickedCh; browser.OpenURL(pm.URL/tr.URL); systray.Quit()
      // optionally open pm.URL in the browser once its port accepts a connection (reuse the
      // existing 40×50ms net.DialTimeout poll loop from the old main.go).
  }

  func onExit() {
      if pm != nil { pm.Close() }
      if tr != nil { tr.Close() }
  }
  ```
- `arx_go/console_windows.go`: move verbatim from `parts_master_go/console_windows.go`
  (`package main`, the `consoleOpen` guard already exists — keep it).
- `arx_go/icon.go` + `arx_go/icon.png`: move the icon-building code from
  `parts_master_go/icon.go` and copy one `icon.png`. One tray icon for the merged app.
- `arx_go/embed.go`: `//go:embed icon.png` if the icon code reads it via embed (match how
  `icon.go` currently loads `iconPNG`).

**D. Runtime config layout (don't skip — first-run will break otherwise).**
- The merged exe's working directory must contain a `config/` folder. Both
  `config.LoadLocal()` calls resolve relative paths: `config/local.pm.json` and
  `config/local.tr.json`. Create `arx_go/config/` with a `.gitkeep` (the two `local.*.json`
  files are gitignored and user-specific).
- `.env` still loads from `../.env` (repo root) then `.env` — unchanged from each app.
- On first run from the new location the user re-enters DB settings via Settings on each
  port; those writes land in `arx_go/config/local.{pm,tr}.json`. Note this in the PR
  description so the user knows to re-enter (or to copy their existing `local.*.json` into
  `arx_go/config/`).

**E. Build, start script, gitignore, docs.**
- `arx_go/build.bat`: model it on `parts_master_go/build.bat`, but:
  - Build output `Arx.exe`.
  - Run tests once from repo root: `go test ./...` (covers both apps + arxlib; replaces the
    two per-app test runs).
  - Inject the version into **both** config packages:
    `-ldflags "-H windowsgui -X arx/parts_master_go/config.AppVersion=%VERSION% -X arx/test_records_go/config.AppVersion=%VERSION%"`
  - Build target is the merged main: `go build ... -o Arx.exe .` run from `arx_go/`.
- **Delete** `parts_master_go/build.bat` and `test_records_go/build.bat` — the dirs are now
  library packages with no `func main`, so `go build -o X.exe .` there would fail. (The root
  `test.bat` from #380 already runs `go test ./...`; keep it.)
- Update `start.ps1` (it currently launches the two separate exes per #349) to launch the
  single `arx_go\Arx.exe`, preserving the `$env:TEST_MODE` toggle.
- Update `.gitignore` to ignore `arx_go/Arx.exe` (and `arx_go/config/local.*.json`). Leave
  the old exe-ignore lines or remove them — they're harmless either way.
- Update `CLAUDE.md`:
  - **Building** section → one build: `cd arx_go & build.bat`, output `Arx.exe`.
  - "Two active Go web apps" → keep, but note they now ship as **one binary** (`arx_go/`)
    serving both, still on ports 4568/4569.
  - The `build.bat` per-app references → point at `arx_go/build.bat`.

### Verify (PR1)

2. `cd arx_go & build.bat` → prints `Built Arx.exe v<x.y.z>`; `go test ./...` passes (build

3. Run `arx_go\Arx.exe`:

   - `http://localhost:4568` loads Parts Master; `http://localhost:4569` loads Test Records.
   - Settings on each port saves and reconnects; confirm `arx_go/config/local.pm.json` and

   - Tray menu: "Open Parts Master" and "Open Test Records" each open the right URL; "Quit"

## PR2 — Handler cleanups (no behavior change) · #371, #370, #373

Branch: `feature/v0.5-handler-cleanup`

These are small, isolated tightenings the merge makes worth doing while the handler code is
fresh. Grep first — several may be `parts_master_go`-only.

#### #371 — `appConfigGet` can't distinguish missing key from DB error · `sev: low`
- `parts_master_go/handlers/handlers.go:110` returns `""` for both "not found" and any DB
  error. Change the signature to `appConfigGet(ctx, key) (string, error)` and add a
  one-line helper `appConfigGetOr(ctx, key, def string) string` for callers that genuinely
  want "or default."
- **Grep `appConfigGet(` in both apps** and update every caller. (`test_records_go` may not
  have this function — confirm; if it doesn't, this is PM-only.)
- **Verify**: build green; settings that read `app_config` (e.g. attachment categories) still
  load; a forced DB error logs rather than silently returning "".

#### #370 — `CheckSchemaVersion` runs on every page load · `sev: low`
- It's already called once at startup (PR1 `New()` / old `onReady`) and stores
  `h.schemaMismatch`. The waste is that list handlers **re-call it per request**.
- **Grep `CheckSchemaVersion(`** in both apps' handlers. At each per-request call site,
  delete the call and rely on the cached `h.schemaMismatch` (already injected into templates
  by `render`). Keep the single startup call. If any handler performs a schema-changing op,
  re-call there only.
- **Verify**: with `DEBUG_MODE=true`, loading a list page issues **no** extra `app_config`
  `schema_version` query (it appears once at startup only). The mismatch banner still shows
  when versions differ.

#### #373 — `txLogger` doesn't log Commit/Rollback in debug mode · `sev: low`
- `parts_master_go/handlers/handlers.go:60` — `txLogger` wraps Exec/Query/QueryRow but
  `Commit`/`Rollback` fall through to the embedded `*sql.Tx`, so end-of-transaction is
  invisible in debug logs. Add:
  ```go
  func (t *txLogger) Commit() error   { t.logFn("COMMIT");   return t.Tx.Commit() }
  func (t *txLogger) Rollback() error { t.logFn("ROLLBACK"); return t.Tx.Rollback() }
  ```
- `test_records_go` likely has no `txLogger`/`beginTx` — **grep `txLogger` / `beginTx`** to
  confirm scope before editing.
- **Verify**: with `DEBUG_MODE=true`, create/update a PO — the SQL log now shows `COMMIT`
  (or `ROLLBACK`) bracketing the statements.

## PR3 — `arxlib/urlutil` consistency + `pf_formula` follow-ups · #375, #385

Branch: `feature/v0.5-urlutil-pfformula`

#### #375 — inconsistent `LOCAL:` path handling · `sev: low`, `area: refactor`
- `arxlib/urlutil`: `IsLocalFile` matches `LOCAL:` case-insensitively; `IsLocalDir` does a
  raw suffix check (`/` or `\`). Align both to the same approach and **document the
  invariant** ("`FILFileName` values are trimmed; the prefix is upper-case `LOCAL:`") in
  `docs/conventions.md` (there is already a `FILFileName` URL-format section there — extend
  it).
- **Grep callers** of `IsLocalFile`/`IsLocalDir` in both apps before changing behavior so you
  don't break a template helper. Keep the change behavior-preserving for existing data
  (which already uses upper-case `LOCAL:`).
- **Verify**: `go test ./arxlib/...` green (add a small table test if the package has tests);
  local file and local-dir attachment links still resolve in both apps.

#### #385 — `pf_formula` deprecation follow-ups · `area: db` · **DECISION REQUIRED**
Read the issue body in full — it lays out two surfaces and two valid resolutions.
- The app already ignores `pf_formula` (#199, done in 0.3.52). But: (1) the
  `trg_test_definition_history` trigger still snapshots the column
  (`SQL/TestRecords.sql` ~320), and (2) `copyFormSteps`
  (`test_records_go/handlers/records.go` ~1829) dropped it from the SELECT/INSERT, so
  duplicating a form sets `pf_formula = NULL` on the copy.
- **Two options — confirm with the user before coding:**
  - **Keep (recommended default, low risk):** restore `pf_formula` to the SELECT/INSERT in
    `copyFormSteps` so copies stay faithful; tighten `SQL/schema.md` wording to
    "app does not evaluate, but preserves on copy." No migration, no data loss.
  - **Drop:** add a migration under `SQL/migrations/` dropping `pf_formula` from
    `test_definition`, the trigger, and `test_definition_history`; update `SQL/schema.md`
    and `FUTURE_GOALS.md`. This **irreversibly orphans** existing values — needs explicit
    user sign-off.
- **Verify (keep option)**: duplicate a form whose steps have `pf_formula` set; confirm the
  copy preserves it. `SQL/*.sql` is reference DDL (not auto-run) — to truly verify a
  migration you must run it against the DB manually.
