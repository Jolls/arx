# Plan — Consolidate config type, DB pool, and per-app duplicates (#419, #420, #424)

## Context

After #413 merged Parts Master (PM) and Test Records (TR) into one binary on one port, three
seams remain. They are pure internal consolidation — **no on-disk, URL, cookie, or DB-schema
change**, so the current user build keeps working identically:

- **#419** — PM and TR still define *two* `config.Config` Go types and two `Load()` functions.
- **#420** — PM and TR each open their own `*sql.DB` pool to the same database, with a
  reconnect dance on settings save (`AfterSettingsSave` → `tr.Reload()`).
- **#424** — Two `RELEASE_NOTES.md` embeds (TR's is dead code after #413) and two identical
  `CheckSchemaVersion` / `ExpectedSchemaVersion = "2"` copies.

Intended outcome: **one** shared `config.Config` type + `Load()`, **one** shared `*sql.DB`
pool injected into both handler packages, **one** RELEASE_NOTES embed, **one** schema-version
constant and check. Same behavior, fewer copies.

`arxlib` (module `arx/arxlib`) is already a dependency of both apps and already hosts the
shared pieces (`config.Base`, `LocalConfig`/`LoadLocal`/`SaveLocal` in `arxlib/config/`,
`db.Connect` in `arxlib/db/`). All shared code below lands there.

**Do the three in order: #419 → #424 → #420.** #419 makes both apps share `arxbase.Config`,
which #420's hook signature and #424's const both rely on.

## Module / import facts (for reference)

| Module | Dir | Import path |
|---|---|---|
| arxlib | `arxlib/` | `arx/arxlib` (config pkg: `arx/arxlib/config`, imported as `arxbase`) |
| parts_master | `parts_master_go/` | `arx/parts_master_go` (config: `arx/parts_master_go/config`) |
| test_records | `test_records_go/` | `arx/test_records_go` (config: `arx/test_records_go/config`) |
| arx_go (main) | `arx_go/` | `arx/arx_go` — imports `partsmaster "arx/parts_master_go"`, `testrecords "arx/test_records_go"` |

Both apps are **library packages** (`package partsmaster` / `package testrecords`) with a
`New()` constructor; `arx_go` is the only `package main`. So changing a `New()` signature only
ripples to `arx_go/main.go` plus any `*_test.go` that calls `New()` — grep for
`partsmaster.New(` and `testrecords.New(` and update all hits.

The re-export-alias pattern is already established: each app's `config/local.go` does
`type LocalConfig = arxbase.LocalConfig`, `var LoadLocal = arxbase.LoadLocal`. We reuse that
same pattern for the `Config` type so the ~418 `cfg.X` / `cfg.*Table()` call sites across both
handler packages keep compiling unchanged.

## Part 1 — #419: one shared `config.Config` + `Load()`

### 1a. Create the merged type in `arxlib/config/config.go` (new file)
- `package config` (the `arxbase` package). Define a single `Config` struct embedding `Base`
  with the **union** of all app-specific fields:
  ```go
  type Config struct {
      Base
      POFolderRoot      string
      SupplierFilesRoot string
      TestRecordsURL    string
      PartsMasterURL    string
      ImageRoot         string
      PODefaults        PODefaults
  }
  type PODefaults struct {
      ContactID  int
      ReceiverID int
  }
  ```
- Move **all** `*Table()` helper methods onto this type — the union of both apps' helpers:
  PM's `PartsTable, AttachmentsTable, BOMTable, PriceTable, POTable, POLineTable, CompanyTable,
  SupplierPartTable, MfgPartTable, CompanyAttachmentsTable, ContactTable, UnitTable,
  AppConfigTable` **plus** TR's `FormsTable, RecordsTable, StepsTable, ResultsTable,
  NamedQueriesTable, TestDefinitionHistoryTable, FormEventsTable, RecordEventsTable`.
  `PartsTable`/`BOMTable`/`AppConfigTable` exist in both today and return the **same** literal
  (`"PN"`, `"PL"`, `"app_config"`) — keep one copy each. No collisions in the union.
- Add the single `ExpectedSchemaVersion = "2"` const here (see #424).

### 1b. Merge the two `Load()` functions into one `arxbase.Load()`
- Source of truth: PM's `Load()` in `parts_master_go/config/config.go:34-117` (it is the
  superset — has the `DATABASE_DSN` backward-compat parse and `PODefaults` mapping). Fold in
  TR's only unique mappings: `PartsMasterURL` and `ImageRoot` env defaults.
- Env/default reconciliation (keep current PM behavior, since the merged app listens on PM's
  port): `Port` from `PM_PORT` || `PORT`, default `"4568"`. Map every field: `POFolderRoot`,
  `SupplierFilesRoot`, `TestRecordsURL` (default `/records` per #413), `PartsMasterURL`
  (default `/`), `ImageRoot`, `PODefaults`. Apply `LocalConfig` overrides exactly as PM does
  today (including PODefaults), and TR's `ImageRoot` override.
- **Before writing, grep `cfg.Port` usage in `test_records_go/`** to confirm TR's port is now
  vestigial (the merged app serves only on `pm.Port`; `tr.Handler()` needs no port). If the
  only readers are logging / the now-removed second server, defaulting to 4568 is safe. If
  something user-visible reads it, note it and keep a `tr` port value — but this is not
  expected.

### 1c. Re-export aliases in both app config packages
In `parts_master_go/config/config.go` and `test_records_go/config/config.go`, **delete** the
local `Config` struct, `PODefaults`, all `*Table()` methods, and the `Load()` body, replacing
with thin re-exports (mirror the existing `local.go` alias pattern):
```go
type Config = arxbase.Config
type PODefaults = arxbase.PODefaults
var Load = arxbase.Load
```
Keep each package's other exported names that handlers import (e.g. anything else still defined
there). Do **not** touch the ~418 `cfg.X` call sites — the alias keeps them compiling.

### 1d. Verify
`cd arx_go && build.bat` (runs `go test ./...` then builds). Fix compile errors only at the
config-package boundary; handler call sites should be untouched.

## Part 2 — #424: retire RELEASE_NOTES + schema-version duplicates

### 2a. One schema-version const + check (lands with #419's `arxbase/config`)
- Single `const ExpectedSchemaVersion = "2"` lives in `arxlib/config/config.go` (added in 1a).
  **Remove** the `const ExpectedSchemaVersion` from both `parts_master_go/config/config.go:18`
  and `test_records_go/config/config.go:17`.
- Add a shared helper in `arxlib/config` (or `arxlib/db`) that runs the check and returns the
  mismatch message (or `""`). Pass the handler's existing logging query wrapper so SQL logging
  is preserved — both wrappers share the signature `func(ctx, query, args...) *sql.Row`:
  ```go
  // CheckSchemaVersion returns "" when the DB schema_version matches, else a message.
  func CheckSchemaVersion(ctx context.Context,
      queryRow func(context.Context, string, ...any) *sql.Row, appConfigTable string) string
  ```
  Body = the current logic from `handlers.go` (SELECT `schema_version` from `appConfigTable`,
  compare to `ExpectedSchemaVersion`, format mismatch / read-error strings identically).
- In **both** `handlers.go`, replace the `CheckSchemaVersion(ctx)` method body with:
  ```go
  func (h *Handler) CheckSchemaVersion(ctx context.Context) {
      if h.db == nil { h.schemaMismatch = ""; return }
      h.schemaMismatch = arxbase.CheckSchemaVersion(ctx, h.queryRowContext, h.cfg.AppConfigTable())
  }
  ```
  Keep the method (callers in both `main.go`/`Reload`/`SettingsSave` are unchanged). Drop the
  now-unused `config.ExpectedSchemaVersion` reference and any now-unused imports.

### 2b. One RELEASE_NOTES embed (drop TR's dead copy)
`go:embed` cannot reach across module dirs, and TR's copy is **already dead** after #413 (no
`/whats-new` route, `releaseNotes` field never rendered). So the minimal retirement is: keep
PM's single embed, delete TR's duplicate and its dead plumbing.
- Delete `test_records_go/RELEASE_NOTES.md`.
- Remove the `//go:embed RELEASE_NOTES.md` + `var releaseNotesData` from
  `test_records_go/embed.go`.
- Drop the `releaseNotesData` argument from the `testrecords.New()` → `handlers.New()` call in
  `test_records_go/main.go:45`, and remove the `releaseNotes` field + constructor param from
  `test_records_go/handlers/handlers.go` (struct field ~line 30, `New()` param ~lines 33-35).
- Remove the dead `/whats-new` link in `test_records_go/templates/layout.html:35` (it already
  points at a route TR no longer serves). PM's `/whats-new` still serves the single embed for
  the whole app.
- Leave `parts_master_go/RELEASE_NOTES.md` as the canonical file. (Note for later #422: when
  the packages collapse, this embed moves to `arx_go`.)

### 2c. Verify
`build.bat` passes. Manually: `/whats-new` still renders PM's notes; Settings page still shows
the notes block.

## Part 3 — #420: one shared `*sql.DB` pool

After #419, both apps share `arxbase.Config`, so the settings-save hook can pass a typed
pool + config across the app boundary. Move pool ownership up into `arx_go`.

### 3a. Inject the pool into both apps
- Change both constructors to accept an injected pool + config instead of loading/opening
  their own:
  - `parts_master_go/main.go`: `func New(database *sql.DB, cfg *arxbase.Config) *App`
  - `test_records_go/main.go`: `func New(database *sql.DB, cfg *arxbase.Config) *App`
  - Each `New()` no longer calls `config.Load()` or `db.Connect()`; it builds the handler
    (`handlers.New(database, cfg, ...)`), builds the router, and calls
    `h.CheckSchemaVersion(context.Background())` as today.
- `arx_go/main.go` `onReady()` — do the load + connect **once**, inject into both:
  ```go
  cfg := arxbase.Load()
  database, err := arxdb.Connect(cfg.DSN())   // nil-safe: if DSN unset, database stays nil
  pm = partsmaster.New(database, cfg)
  tr = testrecords.New(database, cfg)
  pm.SetFallback(tr.Handler())
  ```
  Keep the existing nil-DB path working: when no DSN is configured, `database` is `nil` and
  `RequireAuth` already redirects to `/settings` (unchanged behavior).

### 3b. Reconnect-on-save through one path (avoid double-close)
The shared pool means the **old** pool must be closed exactly once after *both* handlers have
swapped to the new pool. Wire it so PM owns the reconnect + close, and TR only swaps.

- Change the hook signature to carry the new pool + config:
  `parts_master_go/handlers/handlers.go`: `AfterSettingsSave func(*sql.DB, *arxbase.Config)`.
  Add `func (a *App) SetAfterSettingsSave(fn func(*sql.DB, *arxbase.Config))` forwarding to the
  handler (replacing the old `func()` form).
- `parts_master_go/handlers/settings.go` `SettingsSave` — reorder so old pool is closed last:
  ```go
  oldDB := h.db
  newDB, err := db.Connect(h.cfg.BuildDSN(connectWith))   // existing connect logic
  // ... on error, keep current error handling ...
  h.db = newDB
  h.cfg = newCfg            // newCfg = the reloaded *arxbase.Config (as today)
  h.CheckSchemaVersion(r.Context())
  if h.AfterSettingsSave != nil {
      h.AfterSettingsSave(newDB, newCfg)   // TR swaps to newDB WITHOUT closing
  }
  if oldDB != nil { oldDB.Close() }        // close shared old pool once, after TR swapped off it
  ```
- `test_records_go/main.go` / `handlers.go`:
  - **Delete** `App.Reload()` (it opened TR's own pool — no longer used).
  - Modify `SetDBAndConfig(db, cfg)` to **not close the old pool** (remove the close-old block,
    `handlers.go:46-48`). It sets `h.db`, `h.cfg`, and calls `h.CheckSchemaVersion`. PM owns
    closing the old shared pool.
  - `arx_go/main.go`: wire `pm.SetAfterSettingsSave(func(d *sql.DB, c *arxbase.Config){ tr.SetDBAndConfig(d, c) })`.

### 3c. Single shutdown close
Both `h.db` now point at the same pool, so closing both `pm.Close()` and `tr.Close()` would
double-close. In `arx_go/main.go` `onExit()`, close the pool **once**:
- Make `tr.Close()` (or PM's, pick one) **not** close the shared DB. Simplest: have `arx_go`
  hold the `database` handle and call `database.Close()` once in `onExit`; change `pm.Close()`
  / `tr.Close()` so neither closes the shared pool (they keep any non-DB cleanup). Document the
  double-close hazard in a one-line comment at the close site.

### 3d. Verify
- `build.bat` passes (update any `*_test.go` calling the old `New()` / `Reload()` signatures).
- Run `arx_go\Arx.exe` from `arx_go\`:
  - PM parts list and TR forms list (`/records`) both load — confirms one pool serves both.
  - `/settings`: save with a DB password → redirects, **both** a PM page and a TR page load
    without the settings redirect (single reconnect propagated to both).
  - Toggle Test Mode in Settings, save → both PM and TR reflect `ArxDev` (one pool swapped).
  - Quit from systray → no panic / no "sql: database is closed" double-close error in the
    debug console.
