## Structural translation (apply mechanically to the whole file)

1. Drop `USE ArxDev;` (Postgres connection is already scoped to the target DB by the caller).
2. Drop `BEGIN TRANSACTION;` / `BEGIN TRY` / `END TRY` / `BEGIN CATCH...END CATCH` wrapper. Replace with a single implicit statement-by-statement script; wrap the whole body in `BEGIN;` ... `COMMIT;` (plain Postgres transaction — Postgres transactions auto-rollback on error when run via `psql -v ON_ERROR_STOP=1`).
3. Drop `dbo.` prefix from every table reference (`dbo.part_attachment` → `part_attachment`, etc.) — applies to every `DELETE FROM`, `INSERT INTO`, `UPDATE`, `SET IDENTITY_INSERT`.
4. Remove every `SET IDENTITY_INSERT dbo.<table> ON/OFF;` pair — Postgres `GENERATED BY DEFAULT AS IDENTITY` columns accept explicit id values in `INSERT` with no toggle needed.
5. `BIT` literal columns: `1`/`0` → `TRUE`/`FALSE` in every INSERT/UPDATE for boolean columns (`is_active`, `is_supplier`, `is_manufacturer`, `is_locked`, `can_approve_po`, `can_approve_records`, `is_admin`, `pass_fail`, `archived`, `is_lot_tracked`, etc.). Confirm boolean-typed column per table by reading each `SQL/postgres/*.sql` file before translating its INSERT block — do not assume BIT-in-source implies BOOLEAN-in-target without checking.
6. `GETDATE()` → `CURRENT_TIMESTAMP`.
7. Date/datetime string literals (e.g. `'2020-01-01T00:00:00'`, `'2026-05-15'`) — keep as-is; Postgres parses ISO 8601 timestamp/date literals natively, no cast needed.
8. `ISNULL(x, y)` → `COALESCE(x, y)` (used once, in the `stock_on_hand` UPDATE for part 3007).
9. `TOP N` inside embedded SQL text only appears inside `named_queries` seed rows, which are out of scope for this file (see below) — no translation needed here.
10. `DBCC CHECKIDENT ('dbo.<table>', RESEED, N);` block (source section 12, lines 677-698) → replaced by `setval()` calls:
    ```sql
    SELECT setval(pg_get_serial_sequence('<table>', 'id'), N);
    ```
    One line per table in the same DBCC list, same order, same reseed values. SQL Server `RESEED, N` sets the *next* generated value to `N+1`; Postgres `setval(seq, N)` (2-arg form, default `is_called = true`) also makes the *next* `nextval()` return `N+1` — same semantics, values carry over unchanged.
    - Still emit a `setval` line reseeding `named_queries` to 99 even though no rows are inserted here — harmless no-op-safe hygiene consistent with the DDL existing.
11. `PO_Number_Seq` restart block (`IF EXISTS ... ALTER SEQUENCE ... RESTART WITH 9001 ELSE CREATE SEQUENCE ...`) → since `SQL/postgres/purchase_order.sql` already creates `po_number_seq` unconditionally, the seed script only needs:
    ```sql
    ALTER SEQUENCE po_number_seq RESTART WITH 9001;
    ```
12. Trailing `PRINT '...'` success message → drop entirely. No existing `SQL/postgres/*.sql` file emits an informational message; rely on `psql -v ON_ERROR_STOP=1` for failure signaling instead of an explicit success print.
13. Column `SUNotes`, `SUSupplierCode` etc. on `company` — unquoted, lowercase-folded per README's mixed-case rule; no changes needed in INSERT value literals (Postgres folds identifiers, not string literal values).

## Transaction/error-handling resolution
Use a plain `BEGIN; ... COMMIT;` block. No `DO $$ ... EXCEPTION ... END $$;` wrapper — rely on the human running this via `psql -v ON_ERROR_STOP=1` (or equivalent), matching how the rest of `SQL/postgres/*.sql` is run (human-run, not auto-applied).
