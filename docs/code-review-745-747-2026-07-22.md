# Code Review — Traceability slices 8–10 (#745 / #746 / #747)

- **Branch:** `feature/745-747-traceability-render-view-buildux`
- **Date:** 2026-07-22
- **Scope:** working-tree diff vs `main` — tracking_mode migration off `is_lot_tracked`, generalized lot+unit genealogy walk, Units subtab + per-serial trace, build-at-test-time inline panel.
- **Level:** `/code-review high`

## Findings

### 1. (HIGH, correctness) Minted units are never wired into the genealogy graph
- **File:** [arx_go/records.go:2571](arx_go/records.go#L2571) (unit mint); also [arx_go/lot.go:103](arx_go/lot.go#L103), [arx_go/build.go:335](arx_go/build.go#L335)
- The build-at-test-time / serial-save path mints a unit but never inserts a genealogy edge with that unit as a child endpoint. `recordGenealogy` writes only lot→lot edges into the output lot; `upsertUnitForRecord` links the unit via `unit.lot_id`/`build_id`, not via any `genealogy` row.
- **Failure:** Save a lot_serial part's record with the inline build panel. `genealogyTrace(unitID,"unit")` follows only edges where `child_unit_id = unitID`, finds none, and `PartUnitTrace` renders "No component lots or units recorded for this unit yet." The slice-9 "birth certificate" is empty for every unit created through the feature's own code. Only the hand-seeded edges `8404/8405` populate the view, which masks the gap in `TestIntegration_UnitGenealogyTrace`. Plan 747 step (e) (unit-endpoint genealogy edges) is unimplemented.
- **Note:** Likely needs a design decision on how the output unit connects into the edge table (unit→consumed-lot and/or unit→child-unit edges) before implementing.

### 2. (MEDIUM, correctness) No guard against re-building an already-built record
- **File:** [arx_go/records.go:2538](arx_go/records.go#L2538)
- `SaveResults` runs `performBuild` whenever `build_panel=1`, with no check that the still-WIP record was already built.
- **Failure:** User saves a WIP serial record with the panel open (build #1 created, stock consumed, unit minted), returns to edit (record still unlocked), re-opens the panel, and saves again. `performBuild` creates build #2 and re-issues components (real inventory consumed), but `upsertUnitForRecord` finds the existing unit by `(part_id, serial)` and returns it without updating provenance — so nothing references build #2. Silent double stock consumption plus an orphaned build (its `TestedCount` stays 0).

### 3. (LOW–MED, correctness) `tracking_mode` read error silently ignored
- **File:** [arx_go/records.go:2515](arx_go/records.go#L2515)
- The `SELECT tracking_mode` lookup in `SaveResults` discards its error.
- **Failure:** For a lot_serial part, a transient read failure (context cancel, pool hiccup) yields `trackingMode = ""`; `TracksLots("")`/`TracksSerials("")` are both false, so the request skips output-lot creation and unit minting and writes `lot_id`/`build_id` straight onto the record — corrupting the Q8 invariant with no error surfaced.

### 4. (LOW, correctness/altitude) Serial part with blank serial still consumes stock building
- **File:** [arx_go/records.go:2570](arx_go/records.go#L2570)
- The `build_panel` path builds (consuming stock, creating a build) before the serial-empty check.
- **Failure:** A serial/lot_serial record with `serial_number=""` saved with the panel open runs `performBuild` (stock issued, build + output lot created), but the unit upsert is skipped because `serial==""`, so `buildArg`/`lotArg` land on the record's `lot_id`/`build_id` instead of on a unit. Stock is consumed for a unit that was never created.

### 5. (LOW, simplification) `partFromForm` calls `trackingModeFromForm(r)` twice
- **File:** [arx_go/parts.go:680](arx_go/parts.go#L680)
- `partFromForm` invokes `trackingModeFromForm(r)` once for `TrackingMode` and again for `IsLotTracked`, re-reading and re-clamping the same form value. Assign `mode := trackingModeFromForm(r)` once and reuse it for both (as `PartsCreate`/`PartUpdate` already do at [parts.go:491](arx_go/parts.go#L491)/[600](arx_go/parts.go#L600)).

## Resolution (2026-07-22)

1. **FIXED (view-bridge, per decision).** `PartUnitTrace` now seeds the genealogy walk from **both** the unit and its lot (`genealogyTraceRoots`, shared visited set) — a lot_serial unit's as-built components are its lot's, so the birth certificate populates from the consumed-component edges `performBuild` writes into the output lot. No fake edges, no change to the shared build path. Serial-only (build, no lot) unit genealogy is a noted follow-up.
2. **FIXED.** `SaveResults` build_panel path now rejects (400) when the record already has `unit_id`/`build_id` set — no double build / double stock consumption.
3. **FIXED.** The `tracking_mode` read error is now checked (500 on non-`ErrNoRows` failure), so a transient read can't silently downgrade a lot_serial part to `none`.
4. **FIXED.** build_panel rejects (400) a serial/lot_serial record with a blank serial before building, so stock is never consumed for a unit that can't be minted.
5. **FIXED.** `partFromForm` computes `mode := trackingModeFromForm(r)` once and reuses it.

## Checked and clean (not flagged)
- `UQ_unit_serial (part_id, serial_number)` covers the retest TOCTOU race — a concurrent duplicate INSERT fails at the DB.
- `partPageBase` → `tabVisible` gates the new `/units` routes for non-serial parts.
- Autosave (`saveDraft`) only writes localStorage; it does not POST, so it cannot trigger a phantom build.
- The disabled `build_panel` flag and lot pickers keep a collapsed panel inert (no build unless explicitly opened).
- Locked records are rejected at the top of `SaveResults` before any build.
